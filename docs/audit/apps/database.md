## database — PostgreSQL Studio (read-only source audit)

### 1. Purpose, manifest, auth
"Database Studio" (`src/apps/database/manifest.ts:3-46`) is a raw PostgreSQL browser: table list, paginated grid with inline editing, SQL console/EXPLAIN, ER graph, CSV/JSON import, DDL wizard, audit/revert. Category `Operations`, order/dock 14, window 980×640 (min 720×480) at (160,80), icon `Database`, accent `#0a84ff`, badge `SQL`. `shortcut: '⌘D'` is **decorative**: the global handler only acts on manifest `hotkey` (`src/core/shortcuts/useGlobalShortcuts.ts:127-133`), which this manifest lacks, so ⌘D opens nothing. `menu` contains only a title (43-45) → no app menu items or commands; no `notifications` key → no notification kinds. `dockIcon` `/app-icons/database/256.png` does not exist in `public/app-icons/` (DockItem falls back via `onError`, so one guaranteed 404).

Permission text (`:36-42`) sells a `kullan`/`yonet` split and warns it grants full DB access. Enforcement is inconsistent: the client gate is `isAdmin || canUseApp('database')` (`index.tsx:32`), while every server route requires `permission.admin` (`src/lib/server/databaseAccess.ts:86-94`). A role granted only `kullan` therefore opens the window and then gets 403 on every API. Auth chain: session cookie → admin → in-memory freeze (`databaseAccess.ts:66-107`) → HMAC `x-db-token` (30 min, bound only to userId; `databaseAccess.ts:6-47`). Token issuance requires TOTP, or a passkey-authenticated session (`src/app/api/database/auth/route.ts:58-78`), with 8 attempts/15 min (`:11-12,36-46`). The "30-minute idle" expiry is client-only (`index.tsx:72-79`); the token itself stays valid for its full TTL.

### 4. Fields
Sidebar search (string, no API). Grid search → `search` (server ILIKE only over text-ish columns). Page size 50 default; page jump digits. Filters: `column` (existing columns), `op` whitelist, `value` (`is_null`/`is_not_null` hide it), sent as JSON `filters`; server re-validates column/op and binds params. Hidden columns client-only, never reset on table switch. Add row: one text input per non-sensitive column; empty skipped; integers `parseInt` (invalid → NaN → JSON `null`); boolean only `'true'`. Row drawer: text inputs, `NULL/TRUE/FALSE` select for boolean, JSON textarea with live validity hint, disabled masked sensitive field; PK editable. SQL textarea default `SELECT * FROM users ORDER BY created_at DESC LIMIT 50;` plus `bypassSafeMode`, `explain`. Safe-mode challenge (table name or `ONAYLIYORUM`). Import file `accept=".csv,.json"`, mapping select per target column, `conflictStrategy` default `upsert`, no client size/row cap (server caps 2000). Create table: table name (regex), columns `name/type/nullable/isPrimaryKey/defaultValue`; server type allow-list with `TEXT` fallback; `defaultValue` unsanitized. 2FA code: digits, max 8, 6 auto-submits. Dynamic/hidden: JSON prettify only for `json/jsonb`, filter value hidden for null ops, SQL preview toggled.

### 5. Data flow
`GET /api/database/tables` → information_schema + one `COUNT(*)` per table + PK map (`tables/route.ts:40-92`); `POST` create_table/add_column (DDL, WARN log). `GET /data` → columns/PK/FKs, COUNT, `SELECT * ... LIMIT/OFFSET` with masked rows (`data/route.ts:25-218`). `POST /mutate` → transaction of UPDATE/INSERT/DELETE keyed by client PK, writes a `denetim_kaydi` row per update, then `system_logs` (`mutate/route.ts:65-169`). `POST /query` → guarded arbitrary SQL, optional EXPLAIN in READ ONLY, `system_logs` + `security_blocks` strikes. `POST /import` → per-row INSERT/upsert/skip + system log. `GET /schema` → information_schema + per-table COUNT. `GET /audit` reads `audit_logs` (`hedefTur='database_table'`, LIMIT 100); `POST` reverts client-supplied `previous` values. Cross-app: no app-specific calls, but every base table is readable/editable/writable, including other apps' data; no notifications are produced.

### 6. States
Loading spinners for tables/data/schema/audit; empty "noResults", "select table", "no records"; 2FA setup-required/passkey/idle/rate-limited variants. Errors: several fetches only `console.error` and leave stale UI (tables, data, delete, insert); token-401 resets only on tables/data, other screens just show the message; audit GET returns HTTP 200 `{records: []}` on DB failure (`audit/route.ts:37-40`). Raw PostgreSQL messages are returned to the client (mutate 178-181, import 153-157, query 202-208, tables 190-194, audit 119-123).

### 7. Security & privacy
Good: all routes require admin + token; SQL console blocks OS primitives, protected-table mutations, sensitive projections, EXPLAIN breakouts; filters are parameterized. Bad: (a) **guards use stale Turkish names** — `PROTECTED_TABLES` in mutate/import (`mutate/route.ts:16`, `import/route.ts:15`) and `SENSITIVE_COLUMNS` (`mutate:7-14`, `import:6-13`, `audit:8`) target `sistem_loglari/denetim_kaydi/guvenlik_engelleri/…`, but base tables are `system_logs`, `audit_logs`, `security_blocks`, columns `password_hash`, `totp_secret`, `session_token`; old names survive only as views (`schema.init.ts:635,644,950`). So audit logs and password hashes are editable through `/mutate`/`/import`, and `/audit` revert can rewrite them. (b) **DDL injection**: `DEFAULT ${c.defaultValue}` interpolated verbatim (`tables/route.ts:131,170`) while `pool.query(sql)` without values permits multi-statement SQL — this bypasses the SQL console guard entirely. (c) Safe Mode is a client boolean (`query/route.ts:66,100`). (d) Audit diffs are client-supplied `previous` values, so audit history can be forged; revert is not audited and not transactional (`audit/route.ts:89-118`). (e) Deleting/updating by first PK column only: composite PKs are collapsed (`Grid.tsx:84-106`, `index.tsx:445-463`) and missing PKs fall back to `row_N` → silent zero/multi-row changes. (f) Read endpoints expose all rows of `users`, `webauthn_credentials`, `email_verifications`, audit IPs; masking covers only known column names and a few value prefixes (`waf.ts:232-246,330-348`). (g) Freeze is process-local and `unfreezeUserDatabaseAccess` has no caller. (h) No rate limit on query/mutate/import; raw DB errors leak schema. Import never uploads a file server-side and rejects >2000 rows, but no file-size cap or type coercion.

### 8. Tests
Only e2e (`tests/e2e/*.mjs`, `tests/e2e/ui/suites/`); no unit tests, and no file references `/api/database` or `DatabaseApp`. Every behavior above — token/2FA, filters, import, DDL, revert, PK handling — is untested.

### 9. Top 5 defects
1. **DDL injection** through `defaultValue` (`src/app/api/database/tables/route.ts:131,170`; preview in `DatabaseCreateTableModal.tsx:67`) — arbitrary SQL as the DB role.
2. **Dead safety lists**: stale table/sensitive-column names (`mutate/route.ts:7-16`, `import/route.ts:6-15`, `audit/route.ts:8`) vs real schema (`schema.init.ts:85-117,374,529,936`) make audit-log/credential tables editable.
3. **False timeout/read-only guarantees** in the SQL console: `SET LOCAL statement_timeout` outside a transaction (`query/route.ts:145`), Safe Mode bypass trusted from the body (`:66,100`), no row cap.
4. **Client-authored audit trail**: `previous`/`hedefId` come from the mutation payload (`mutate/route.ts:98-112`) and drive unscoped revert (`audit/route.ts:89-104`); deletes/inserts are never audited.
5. **N+1 count/refetch storms**: COUNT per table on every table list (`tables/route.ts:71-90`, `schema/route.ts:110-118`), and `fetchTables` is retriggered whenever `selectedTable` changes (`index.tsx:165-176`), plus per-keystroke search (`Grid.tsx:521-524`).

### 10. Daha iyisi yapılabilir
Use one shared safety module (English names + allow-list of editable tables/columns); skip audit_logs/system_logs/webauthn tables entirely. Parameterize or validate DDL defaults as literals, and run DDL through the same guard. Bind the DB token to the auth session, enforce idle server-side, and add a revoke/unfreeze path. Make mutate return affected row counts and require a real, unique PK; send composite keys. Write audit entries server-side from before/after reads and record reverts as new entries in a transaction. Replace the `isSensitive` name heuristic with a server-provided column policy and never send sensitive values at all. Add debounce, server-side pagination/count caching, and export-all. Label icon buttons with `aria-label`, reset hidden columns on table switch, fix the "LIKE starts-with" label, and surface fetch failures instead of `console.error`. Add API/e2e coverage for every endpoint, including negative authorization and injection cases.
