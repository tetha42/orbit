## certificates — Credentials & Badges (`src/apps/certificates`)

### 1. Purpose & manifest surface

Public, verifiable credentials: a member sees their own certificates, badges, XP level and club leaderboard; managers issue/revoke certificates and edit what the printed document says. `manifest.ts:2-24` declares `id: certificates`, category Community, dock icon `keynote/256.png`, window 820×560 (min 640×420) at (190,80), `shortcut: '⌘5'`, `hotkey: '5'`, order 4, dock 6 (`manifest.ts:25-37`). Notification kind `certificate: 'kullan'` (`:41`) is the only kind the app publishes; `permission` (`:42-46`) gives `kullan` = own certificates + PDF, `yonet` = issue/revoke/signatories. Menu has exactly one item, `about-certs` "Sertifika Doğrulama Hakkında", `permission: kullan`, `ac: true` (`:47-50`). Shortcut/hotkey are executed by the shell (`src/core/shortcuts/useGlobalShortcuts.ts:127-130`), not by the app.

Authorization is server-authoritative: GET list `requireApp(...,'kullan')` and self-scoping unless manager (`src/app/api/certificates/route.ts:8-16`); POST/DELETE `requireApp(...,'yonet')` (`:29`, `:81`); signatories PATCH allows `settings:yonet` **or** `certificates:yonet` (`src/app/api/community/route.ts:28-32`). Client mirrors this with `canManageApp('certificates')` (`hooks/useCertificates.ts:20`) purely for rendering.

### 2. Component map

`index.tsx` (desktop/mobile switch at `:23-31`) → toolbar, badges, list, detail modal, signatories modal, issue modal, leaderboard. State and all mutations live in `hooks/useCertificates.ts`; presentation components are thin. Public surfaces outside the app: `/api/certificates`, `/api/sertifikalar` (re-export), `/api/certificates/[code]`, `/dogrula/[kod]` → `verify/[kod]/page.tsx`.

### 4. Field inventory

Issue: recipient `<select required>` (options `/api/members`, empty when the role lacks members access), title `<input required>` defaulted to the localized TEKNOFEST preset (only at first render), event `<select required in bulk>` (single mode shows all events, bulk only events with attendees), category `<select>` achievement/participation/service/honor, language `<select>` tr/en, context `<input>` free text. Payload: `userId`, `baslik`, `etkinlikId?`, `kategori`, `dil`, `aciklama?`; bulk sends `action:'bulk'` instead of `userId`. Server validates only title (trim, 1-160) and recipient existence (`route.ts:35-38,58-61`); `kategori`/`dil` are any string, `aciklama` has no length cap, `etkinlikId` is not existence-checked for single issue, and `pdfUrl` is accepted though no UI ever sends or renders it (`types.ts:12`, `certificates.repo.ts:70-79`). No file/date/toggle inputs exist in this app; dates are server-set.

Signatories: university, club name, signatory name (optional) and title per row, all maxLength 80; `PATCH` requires exactly two rows and rejects empty university/club/title (`community/route.ts:42-50`).

### 5. Data flow

`GET /api/certificates` → `getCertificates(userId?)` selects `sertifikalar s JOIN kullanicilar k LEFT JOIN etkinlikler e`, plus `k.ogrenciNo` (`certificates.repo.ts:13-33`). Manager-only `POST` inserts through the Turkish `sertifikalar` view over `certificates` (`:54-91`), retrying code collisions (`BEU-YYYY-XXXX-XXXX`, 31-char alphabet, `:6-11,66-90`), then publishes a `bildirim` hint to the recipient (`:85`). Bulk reads `yoklamalar` for the event and calls `createCertificate` per attendee (`:93-123`). DELETE is a hard `DELETE ... WHERE id=$1` (`:150-154`). Reads also come from `/api/community` (`getCommunityProfile`, system settings + admin-name fallback), `/api/events`, `/api/members`, `/api/profile` (`ozet.sertifika` from `users.repo.ts:146`). Cross-app writes: signatories go to `system_settings` via the settings/community API. Notifications read the same list for the 14-day feed (`src/app/api/notifications/route.ts:83,236-247`) with `kullan` gating; search scopes to own/manager (`src/app/api/search/route.ts:99,246-261`). No audit row is written for issue or revoke.

### 6. States

Loading is conflated with empty: `certificates` is `[]` until the request returns, so the list immediately renders "Henüz bir sertifika bulunmuyor" (`CertificatesList.tsx:43-58`); `useJsonResource`'s `error`/`failure`/`httpStatus` are never read by the hook, so a 403/500 read is indistinguishable from "no data". Badges render nothing until `/api/profile` returns (`BadgesGrid.tsx:25`). Leaderboard has no empty state and no error state — an empty table with headers. Mutation errors appear as a 4-second inline banner (`CertificatesToolbar.tsx:52-66`); PDF errors go to a no-op `onError` (`index.tsx:124`, mobile `:230`), so the button appears dead. Server error bodies are generic Turkish strings; no stack/SQL is returned. The signatories modal renders the server's own validation text (`SignatoriesModal.tsx:44-47`).

### 7. Security & privacy

Strengths: list is self-scoped unless manager; writes require `yonet`; verification strips `userId` and `ogrenciNo`; verification JSON is IP-banned, WAF-checked and limited to 30/min (`[code]/route.ts:12-41`). Gaps: the HTML verification pages call `getCertificateByCode` directly with no rate limit, ban or WAF (`verify/[kod]/page.tsx:20`), so the API's protection is bypassable; the JSON response still returns, besides name/title/description, the internal UUID, `etkinlikId`, department and `pdfUrl` (`[code]/route.ts:51-61`). Every member's list payload carries `ogrenciNo` (`certificates.repo.ts:18`) that the UI never displays. No IDOR on DELETE (manager + id only, no owner check needed) but any manager can delete any certificate. `pdfUrl` is unvalidated manager-supplied input stored and echoed to the public response. Revocation is hard delete: no revocation record, no reason, no audit, and the holder gets no notification. `SignatoriesModal` is client-gated but server also accepts `settings:yonet`, so a settings manager can rewrite certificate letterhead from another app.

### 8. Tests vs untested

`tests/e2e/ui/suites/sertifikalar.mjs` covers badges, single/bulk issue, PDF, public verify, revoke, RBAC, plus dock lists in other suites. It is stale against the code: it sends `?kullaniciId=` (`:23,146`) while the route reads `userId` (`route.ts:13`), reads `c.dogrulamaKodu` while the API returns `verificationCode`, expects badge `gorev-avcisi` while `lib/badges.ts` defines `task-avcisi`, and expects "Dijital Sertifika Doğrulandı" while the page prints "Dijital Certificate Doğrulandı". Worse, `certsOf(admin, id)` ignores the filter, so its cleanup (`:24-26`) deletes **every** certificate in the database. Untested: leaderboard, LinkedIn deep link, context menu, signatory save, copy/Clipboard failure, mobile view, `/verify` page (only `/dogrula`), notification deep link, and 403/500 UI states.

### 9. Top five defects

1. **Bulk issuance is not atomic.** N sequential `INSERT`s and N notifications with no transaction (`certificates.repo.ts:99-121`); one failure returns 500 after half the attendees already hold a certificate, and the client cannot tell how many were issued.
2. **No audit trail and no revocation record.** Issue (`repo:85`) and hard delete (`repo:150-154`, `route.ts:80-101`) write no `audit_logs` row, unlike member/settings writes; "revoked" is indistinguishable from "never existed".
3. **Recipient picker couples certificates to the members app.** `members` are fetched only when `canUseApp('members')` (`hooks:45-48`); a role with only `certificates:yonet` sees an empty required select and cannot issue anything, although the server would accept any `userId` (`route.ts:58-71`).
4. **Silent failures and a lying copy state.** PDF errors are swallowed by `onError={() => {}}` (`index.tsx:124`); one global `copied` boolean (`hooks:25,63`) flips every card's label to "Kopyalandı" and clipboard rejection is never awaited/caught (`hooks:60-66`).
5. **Public verification over-exposure with inconsistent limits.** The page bypasses rate limiting (`verify/[kod]/page.tsx:20`) and the API returns the internal UUID/event/department/`pdfUrl` (`[code]/route.ts:51-61`); recipient name and free-text description are enumerable to anyone holding a code.

### 10. Daha iyisi yapılabilir

Validate `kategori`/`dil` against the enum and cap `aciklama`; make bulk a single transaction returning per-recipient results; add a soft-revoke (`revokedAt`, `revokedBy`, reason) with an audit row and a notification to the holder; write a `certificate` audit entry for issue and revoke. Decouple the recipient picker by exposing a minimal, certificate-issuer-safe member lookup (id + name), or accept free-text recipient. Read `isLoading`/`error`/`httpStatus` in the hook and render real loading/error states instead of an empty list. Give the detail modal an `aria-label` on its close button, real `aria-pressed` on tabs, and per-card copied state. Route verification-page lookups through the same throttled/WAF path or share the limiter, and trim the public response to name/title/description/code/date. Add "copy failed" and "PDF failed" user feedback, reset all issue-form fields after success, and fix or delete the outdated e2e suite — especially its destructive cleanup query.
